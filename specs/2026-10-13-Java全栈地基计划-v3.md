## 0. 怎么用这份文档

**阅读顺序**：先看 §1 存量 → 再看 §3 执行顺序 → 执行时按需查 §6–§9 的阶段明细。§4、§5 是前置规则，动手前读一遍即可。

**每条内容的角色标记**（全文统一）：

| 标记 | 含义 | 你能怎么处理 |
|---|---|---|
| **【主】** | 主轴，串行推进 | 必须按顺序做 |
| **【纪】** | 纪律，全程贯穿 | 不存在"跳过"，只存在"做得够不够" |

| **【补】** | 补丁，遇到问题才查 | 用到再点开 |

**三条硬规则**
1. 任何"做完"的定义是**测试全绿或契约通过**，不是"看起来能跑"
2. 遇到问题先自己看 Network / Console / 日志，再问 AI
3. 每周固定回顾：本周 AI 写的代码里，有多少你能逐行讲清楚？比例应逐周上升

## 2. 目标边界与不做的事

### 明确不做（中途不碰）

- **Canvas / Three.js**：细分方向，与目标无关
- **React / Next.js**：栈已锁定 Vue + Java，全年不换栈不追新
- **Node.js 后端**：不作后端方向；概念了解即可（事件循环非阻塞，P1 已学）
- **Spring Cloud 微服务**：概念了解即可，不深入（一个人维护微服务是自虐）
- **K8s / 服务网格**：不碰
- **DBA 级调优**（分库分表、读写分离实战）：不学，用到再查
- 移动端原生开发、游戏开发：同理暂缓

### 判断原则

放弃「死记语法、背 API、手写样板 CRUD、背八股题、追微服务新名词」，
转向「懂原理、能判断、会调试、架构与契约设计、真实项目的排错与审阅」。

## 4. 贯穿全程的 AI 协作主线【纪】

### 4.1 五条协作法则

1. **先想后写**：自己先做设计（目录结构、模块划分、状态流、接口契约、表结构），再让 AI 按你的骨架实现
2. **小步审阅**：每次只让 AI 改一个明确的小功能，逐行读懂后再继续
3. **断点验证**：用调试器跟踪执行流，验证自己的理解，而不是只看运行结果
4. **盲写核心**：业务核心逻辑亲手重写一遍，样板代码交给 AI
5. **先复现后修复**：遇 bug 走「复现 → 定位 → 修复」流程，禁止直接让 AI 猜

判断标准：你是在「审阅代码」还是在「盲收代码」。后者就停下来补理解。

### 4.2 协作能力的五个层次

| 层次 | 能力 | 识别标准（做到了是什么样） |
|---|---|---|
| 1 提问 | 把需求写成 AI 能吃的上下文 | 一次说清目标、约束、边界、验收标准 |
| 2 约束 | 用 rules / AGENTS.md 固定项目约定 | AI 不用每次被提醒目录规范、命名、分层 |
| 3 验收 | 用测试与契约定义「做完了」 | 测试全绿 / 契约通过才算完，不靠肉眼 |
| 4 审阅 | 逐行读懂并定位错误 | 断点或日志能指到具体文件行 |
| 5 编排 | 拆任务、分步骤、控上下文 | 一个大需求能自主拆成可逐小步审阅的任务 |

### 4.3 各阶段的协作产物（逐阶段沉淀）

| 阶段 | 产物 | 用途 |
|---|---|---|
| P1 | 审阅 checklist | 拿到 AI 代码先过一遍的固定检查点 |
| P2 | 接口契约模板 + 提示词模板 | 契约先行，AI 按契约实现 |
| P3 | 部署 SOP + 环境说明 | 每一步可复现，AI 出错能回滚 |
| P4 | 项目级 AGENTS.md / rules | 整项目约定固化，AI 接手即合规 |

**目标**：建立框架心智（IoC/DI/AOP）、能独立写 RESTful API 并与前端联调。

**内容**
- Java Web 速过：HTTP 协议从服务端视角回顾（阶段三已学前端视角）、Servlet 概念（了解即可）
- **Maven**：依赖管理、生命周期（**与 npm 类比学**：pom.xml ≈ package.json）
- Spring 核心：IoC/DI、AOP 概念（注解方式为主，不深入字节码）
- Spring Boot：控制器、参数绑定、参数校验、统一响应体、全局异常处理
- **MyBatis-Plus**：CRUD、条件构造器、分页插件、代码生成器
- 接口设计：RESTful 规范、状态码语义、DTO/VO 分层
- 接口文档：Knife4j（Swagger 的国内增强）
- 前后端联调：跨域、token 传递、Postman
- **工程补齐**：文件上传与对象存储（本地存储 + 兼容 S3 的 OSS、签名 URL 概念）、定时任务（`@Scheduled`）与异步任务（`@Async`、线程池配置）、结构化日志与日志分级、基础可观测性（请求日志 / trace id 贯穿、慢接口定位）

**实践任务**（商城项目真实 API，**微项目早贯通**的落点）
- 用户模块：注册/登录（先内存校验，下阶段接 Redis/JWT）
- 商品模块：列表（分页+条件查询）/详情
- 订单模块：创建/列表（核心逻辑亲手写，样板代码给 AI）
- 每个接口先写 **OpenAPI 契约（Knife4j）再实现**——契约先行贯穿全程
- **工程补齐**：实现一次文件上传并落到对象存储；写一个定时任务；给所有接口加 trace id 日志，并靠日志定位一次慢请求

**资源**：B 站搜「黑马 SpringBoot」「尚硅谷 SpringBoot」「雷丰阳 SpringBoot」（挑 2023 年后版本）；MyBatis-Plus 官方文档必读；Spring 官方 Guides 当字典。

**验收**
- [ ] 能解释「Controller → Service → Mapper」每层职责，AI 把逻辑写错层时能指出
- [ ] 商城后端跑起来，Vue/uni-app 前端能调通登录/商品接口
- [ ] 能独立用 Postman 完成接口自测
- [ ] **能独立完成文件上传与定时任务，并靠日志定位一次慢请求**

### 7.4 阶段八：Redis + 鉴权 + 安全【主】

**内容**
- Redis：五大数据类型、持久化概念、缓存应用（商品缓存、token 存储）、缓存穿透/雪崩概念
- JWT：结构（header.payload.signature）、access/refresh 双 token 流程
- 鉴权框架：**Sa-Token**（轻量，优于 Spring Security 对新手的负担）；Spring Security 概念了解即可
- 服务端防护：SQL 注入、XSS、越权访问、敏感信息不落前端
- 接口限流概念

**实践任务**：商城登录注册全链路接入 JWT + Redis；管理端接口加权限校验。

**资源**：B 站搜「黑马 Redis」；Sa-Token 官方文档（sa-token.dev3.cn）必读。

**验收**
- [ ] 能画出双 token 登录时序图并讲清为什么需要 refresh token
- [ ] 越权测试：普通用户调管理端接口返回 403
