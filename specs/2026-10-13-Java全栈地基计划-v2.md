## 贯穿全程的 AI 协作主线（每周项目都按此执行）

### 五条协作法则

1. **先想后写**：自己先做设计（目录结构、模块划分、状态流、接口契约、表结构），再让 AI 按你的骨架实现
2. **小步审阅**：每次只让 AI 改一个明确的小功能，逐行读懂后再继续
3. **断点验证**：用调试器跟踪执行流，验证自己的理解，而不是只看运行结果
4. **盲写核心**：业务核心逻辑亲手重写一遍，样板代码交给 AI
5. **先复现后修复**：遇 bug 走「复现 → 定位 → 修复」流程，禁止直接让 AI 猜

判断标准：你是在「审阅代码」还是在「盲收代码」。后者就停下来补理解。

### 协作能力的五个层次（学什么）

| 层次   | 能力                         | 识别标准（做到了是什么样）        |
| ---- | -------------------------- | -------------------- |
| 1 提问 | 把需求写成 AI 能吃的上下文            | 一次说清目标、约束、边界、验收标准    |
| 2 约束 | 用 rules / AGENTS.md 固定项目约定 | AI 不用每次被提醒目录规范、命名、分层 |
| 3 验收 | 用测试与契约定义「做完了」              | 测试全绿 / 契约通过才算完，不靠肉眼  |
| 4 审阅 | 逐行读懂并定位错误                  | 断点或日志能指到具体文件行        |
| 5 编排 | 拆任务、分步骤、控上下文               | 一个大需求能自主拆成可逐小步审阅的任务  |

### 各阶段的协作产物（逐阶段沉淀，不是一次性文档）

| 阶段 | 产物                    | 用途                 |
| -- | --------------------- | ------------------ |
| P1 | 审阅 checklist          | 拿到 AI 代码先过一遍的固定检查点 |
| P2 | 接口契约模板 + 提示词模板        | 契约先行，AI 按契约实现      |
| P3 | 部署 SOP + 环境说明         | 每一步可复现，AI 出错能回滚    |
| P4 | 项目级 AGENTS.md / rules | 整项目约定固化，AI 接手即合规   |

## P2 Java 后端主线（2026.12 - 2027.04，16 周 / ~350h）

> 新增主线。原则：Java 语法已学过 → SE 只做**唤醒 + 补前端经验里没有的心智**（OOP/集合/多线程/JVM）；数据库按零基础排期但按「**会用 + 懂原理**」定深度；Java 生态文档质量高，**官方文档与视频并重**；全年不换栈。

### 阶段五：Java SE 恢复与补心智（第 12-14 周 / ~60h）

**目标**：能独立用面向对象思想写一个多类协作的程序，并能读懂 AI 生成的现代 Java 代码。

**内容**：

- 语法唤醒：数据类型、流程控制、数组、字符串（`String`/`StringBuilder`）
- 面向对象：封装、继承、多态、接口、抽象类、内部类（**重点**：前端经验里没有的心智）
- 集合框架：`List`/`Set`/`Map`、`ArrayList` vs `LinkedList`、`HashMap` 原理（哈希+链表/红黑树常识）
- **现代 Java 表达（新增）**：Lambda 表达式、函数式接口（`Function`/`Consumer`/`Supplier`/`Predicate`）、**Stream API**（filter/map/reduce/collect、惰性求值）、`Optional` 的用法与误用边界
- 异常处理、泛型（对照 TS 泛型学）、注解常识
- IO 流基础、多线程（线程创建、`synchronized`、线程池概念）
- **Java 版本与语言演进（新增）**：JDK 17 / 21 的选择理由（LTS）、`record`、`sealed` 类、`instanceof` 与 `switch` 的模式匹配、**虚拟线程（Loom）**&#x7684;概念与适用场景
- JVM 常识：内存结构（堆/栈/方法区）、GC 基本原理

**实践任务**：

- 用 Java 重写前端阶段手写的工具（EventEmitter、深拷贝），对照两种语言心智差异
- **用 Stream 改写上述工具的关键步骤，对照命令式 vs 声明式写法**
- 控制台版图书管理系统（多类协作：Book/User/Service/Main）

**资源**（B 站搜索关键词）：「黑马 JavaSE」「尚硅谷 JavaSE」「韩顺平 java」；JVM 部分搜「尚硅谷 JVM」选看基础章；**现代 Java 与新特性**：Oracle 官方《Java Language Updates》按版本读，虚拟线程搜「Java 21 虚拟线程」。

**验收**：

- [ ] 不看资料能写一个含 3+ 类、含集合与异常处理的控制台程序
- [ ] 能解释 `HashMap` 为什么快、`synchronized` 锁的是什么
- [ ] **能逐行读懂 AI 生成的 Stream 链式代码，并说明每一步在做什么**
- [ ] 能说清 `record` / 虚拟线程各自解决什么问题、什么时候该用

### 阶段六：MySQL 从零到懂原理（第 15-17 周 / ~60h）

**目标**：独立完成商城库表设计，并能解释每张表、每个索引为什么这么建。深度 = **会用 + 懂原理**，分库分表等 DBA 级内容明确不学。

**内容**：

- SQL：增删改查、条件/排序/分组聚合、多表（join 一对多/多对多）、子查询
- 数据库设计：三大范式、ER 图、命名规范
- 索引：B+ 树原理（为什么索引快）、聚簇/非聚簇索引、联合索引与最左前缀、索引失效场景
- 事务：ACID、隔离级别、MVCC 概念、脏读/不可重复读/幻读
- 存储引擎：InnoDB vs MyISAM（知取舍）
- 工具：MySQL 8 安装 + DBeaver/Navicat

**实践任务**：

- 为商城项目设计完整表结构（用户/商品/分类/购物车/订单/订单项/地址/支付记录，8+ 张表），含外键与索引设计说明文档
- 手写 20 条查询 SQL（统计类/分组类/多表类）

**资源**：B 站搜「尚硅谷 MySQL」「黑马 MySQL」；选学经典「MySQL 45 讲」（极客时间，文笔好但非必看）；官方 MySQL 文档当字典。

**验收**：

- [ ] 商城库表设计文档能脱稿讲清每张表每个索引的理由
- [ ] 能用 `EXPLAIN` 判断查询是否走索引

### 阶段七：Java Web + Spring Boot + MyBatis-Plus（第 18-23 周 / ~120h）

**目标**：建立框架心智（IoC/DI/AOP）、能独立写 RESTful API 并与前端联调。

**内容**：

- Java Web 速过：HTTP 协议从服务端视角回顾（P1 阶段三已学前端视角）、Servlet 概念（了解即可，快速过）
- **Maven**：依赖管理、生命周期（**与 npm 类比学**：pom.xml ≈ package.json）
- Spring 核心：IoC/DI、AOP 概念（注解方式为主，不深入字节码）
- Spring Boot：控制器、参数绑定、参数校验、统一响应体、全局异常处理
- **MyBatis-Plus**：CRUD、条件构造器、分页插件、代码生成器
- 接口设计：RESTful 规范、状态码语义、DTO/VO 分层
- 接口文档：Knife4j（Swagger 的国内增强）
- 前后端联调：跨域、token 传递、Postman
- **工程补齐（新增）**：文件上传与对象存储（本地存储 + 兼容 S3 的 OSS、签名 URL 概念）、定时任务（`@Scheduled`）与异步任务（`@Async`、线程池配置）、结构化日志与日志分级、基础可观测性（请求日志 / trace id 贯穿、慢接口定位）

**实践任务**（商城项目真实 API，**微项目早贯通**的落点）：

- 用户模块：注册/登录（先内存校验，下阶段接 Redis/JWT）
- 商品模块：列表（分页+条件查询）/详情
- 订单模块：创建/列表（核心逻辑亲手写，样板代码给 AI）
- 每个接口先写 **OpenAPI 契约（Knife4j）再实现**——契约先行贯穿全程
- **工程补齐**：实现一次文件上传并落到对象存储；写一个定时任务；给所有接口加上 trace id 日志，并靠日志定位一次慢请求

**资源**：B 站搜「黑马 SpringBoot」「尚硅谷 SpringBoot」「雷丰阳 SpringBoot」（挑 2023 年后版本）；MyBatis-Plus 官方文档必读；Spring 官方 Guides 当字典。

**验收**：

- [ ] 能解释「Controller → Service → Mapper」每层职责，AI 把逻辑写错层时能指出
- [ ] 商城后端跑起来，Vue/uni-app 前端能调通登录/商品接口
- [ ] 能独立用 Postman 完成接口自测
- [ ] **能独立完成文件上传与定时任务，并靠日志定位一次慢请求**
